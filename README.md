# qms-kb-assistant：医疗器械质量体系文档问答（带版本、权限、审计）

个人项目，数据全部为虚构示例。

> **一句话**：让质量、研发人员用自然语言查 SOP / 验证报告 / 风险文件，同时保证**不答旧版、不越权、不编造、每次回答可追溯**。

**亮点**

- **版本感知检索**：默认只用生效版本；问「旧版 / 变更前」才放出作废版本并显式标注。版本陷阱题旧值误答从 3/6 降到 0/6。
- **权限前置**：按密级在检索前过滤（Milvus 标量过滤 / 规则过滤两种实现），点名无权文件直接返回 `NO_PERMISSION`。越权泄露从 4/4 降到 0/4。
- **可答性门槛**：资料没有答案就拒答，不让模型自由发挥。无答案题正确拒答从 0% 到 100%。
- **全链路审计**：每次问答记录提问人、检索到的片段及版本、管线版本、知识库指纹，满足合规追溯。
- **诚实评测**：开发集 + 留出集分开报（100% vs 7/12），并用留出集发现了一个检索层解决不了的问题——**低密级文件引用高密级结论导致的间接泄露**，需要在入库阶段做治理。

**技术栈**：Qwen2.5（vLLM / Ollama 私有化部署）· bge-m3 · Milvus（HNSW）· BM25 + 向量混合召回（RRF）· LangChain · FastAPI · scikit-learn · unittest

| 版本 | 内容 | 依赖 |
|---|---|---|
| 离线规则版（`qms_kb/`） | 全部评测数字来自这个版本，任何电脑几秒跑完 | numpy、scikit-learn |
| 完整技术栈版（`stack/`） | bge-m3 + Milvus Lite 建库、LangChain + Qwen 带引用生成并校验引用、FastAPI 服务 | 见 requirements-stack.txt |

医疗器械公司的研发和质量资料（SOP、设计输入、验证报告、风险管理、CAPA、变更单）有三个特点，普通的「向量检索 + 大模型」容易出问题：

1. **同一份 SOP 有新旧版本**：旧版被检索出来、答成旧参数，本身就是质量风险；
2. **有密级**：质检员、客服、质量经理能看的不一样，不能靠模型自觉不说；
3. **精确词多**：文件编号、标准号、数值单位，纯语义检索容易漏。

这个项目把这三件事放在检索**之前**和**之后**用规则管住，并用一套评测证明每一步的作用。

## 管线

```
问题 + 提问人
  → 权限过滤（按密级，检索前就过滤，模型根本看不到）
  → 版本过滤（默认只用生效版；问「旧版 / 变更前」才放出已作废版本，并标注【已作废版本】）
  → 混合检索（BM25 + TF-IDF 字符 n-gram，RRF 合并；文件编号 / 数值单位精确命中加分）
  → 可答性门槛（关键词覆盖不足、或问到资料库没有的编号 → NOT_FOUND）
  → 回答（默认抽取式，每句标出处：文件号 + 版本 + 章节；可切换本地大模型）
  → 审计日志（谁、什么时候、问了什么、检索到哪些片段及版本、管线版本、知识库指纹）
```

点名一份存在但无权查看的文件时，返回 `NO_PERMISSION`，不返回任何内容。

## 评测

30 道开发题 + 12 道留出题。题型：版本陷阱、历史版本、普通、编号精确查询、越权、无答案。

开发集（规则在这套题上调过）：

| 管线 | 总准确率 | 版本题答对 | 答成旧版数值 | 越权泄露 | 无答案题正确拒答 | 引用正确 |
|---|---|---|---|---|---|---|
| 只用相似度检索 | 57% | 33% | 3/6 | 4/4 | 0% | 100% |
| + 权限/版本过滤 + 混合检索 | 80% | 100% | 0/6 | 0/4 | 0% | 100% |
| + 可答性门槛（完整版） | 100% | 100% | 0/6 | 0/4 | 100% | 100% |

留出集（规则调完之后才写，没有针对它调）：

| 管线 | 准确率 |
|---|---|
| 只用相似度检索 | 3/12 |
| + 权限/版本过滤 + 混合检索 | 5/12 |
| + 可答性门槛（完整版） | 7/12 |

**开发集 100% 不代表真实水平，留出集 7/12 才是。** 写出来是为了说明：规则调得再好，换种问法就会掉。

## 留出集暴露的问题（比分数更有价值）

| 题 | 现象 | 原因 | 改进方向 |
|---|---|---|---|
| T01「抽检数量」/ T05「从冰箱拿出来」 | 误拒答 | 字面不匹配：文档写「抽样」「冷藏」 | 换语义向量模型（如 bge-m3）或让大模型判断可答性；业务同义词表 |
| T07「剂量范围」 | 答错句子 | 抽取式只挑重合最多的一句 | 接大模型生成（`--generator llm`） |
| T04「以前的上限」 | 答对数值但没标作废 | 答案来自变更单（生效文件）而非旧版 SOP | 评测口径要定：从变更单回答是否可接受 |
| **T09 越权** | **质检员问到了「机密」风险报告的结论** | **内部级的变更单引用了机密报告的结论** | **这不是检索问题，是数据治理问题：低密级文件引用高密级内容时要标注或继承密级** |

T09 是最有意思的发现：权限过滤只能管住文件，管不住「文件之间的引用」。真实落地时需要在入库阶段检查跨文件引用。

## 运行

```bash
pip install numpy scikit-learn requests
python -m qms_kb.run_eval                     # 评测，结果写到 results/
python -m unittest discover -s tests -t .     # 9 个测试

# 接本地大模型（Ollama，数据不出本机）
ollama pull qwen2.5:7b
export LLM_BASE_URL=http://localhost:11434/v1 LLM_MODEL=qwen2.5:7b
python -c "from qms_kb.assistant import Assistant, User; print(Assistant(generator='llm').ask('注射力测试每批抽多少支？', User('张工','质检员','内部'))['answer'])"
```

## 文件

```
qms_kb/docs.py       虚构 QMS 文档（10 份，含新旧版 SOP、变更单、机密报告）+ 按章节切分
qms_kb/retrieve.py   BM25 + TF-IDF 混合检索、RRF、精确词加分
qms_kb/assistant.py  权限 / 版本过滤、可答性门槛、带出处回答、本地大模型接口、审计日志
qms_kb/evalset.py    30 道开发题 + 12 道留出题
qms_kb/run_eval.py   三条管线对比评测
results/             report.md、per_question.csv、audit_*.jsonl（审计日志样例）
```

## 局限

- 文档是我按常见 QMS 结构虚构的，规模很小；
- 中文按字切分，没有分词和语义向量；
- 默认生成器是抽取式的，是下限；LLM 生成的效果没有在这里评测。
